# 令和2年 簡易100mメッシュ人口

[English](../../en/gtfs-gis/population-mesh-100m-2020/README.md)

西澤明さん（東京大学空間情報科学研究センター）が作成し、GTFS-GIS.jp で公開している「令和2年簡易100mメッシュ人口」です。令和2年（2020年）国勢調査の250mメッシュの人口を、建物の面積に応じて100mメッシュに按分した推計人口です。全国の総人口と年齢区分別の人口を、1メッシュ1行のポリゴンで持ちます。事故の件数を人口で割る、駅や学校から一定の範囲の人口を数える、といった集計に使えます。

- ファイル: [`gtfs-gis-population-mesh-100m-2020.parquet`](https://catalog.shi-works.com/gtfs-gis/population-mesh-100m-2020/gtfs-gis-population-mesh-100m-2020.parquet)（GeoParquet 1.1、約172 MB）
- 件数: 4,979,919行（人口を配分した100mメッシュごとに1行。人口のないメッシュの行はない）
- 範囲: 日本全国。2020年10月1日時点（国勢調査の調査日）
- 総人口の合計: 126,128,118人（国勢調査の公表値は126,146,099人）
- 座標参照系: EPSG:4326（緯度経度）。元データは JGD2000（EPSG:4612）で、値はそのまま

## 使い方

DuckDB で、ダウンロードせずに読めます。東京都千代田区のあたり（東経139.73〜139.78度、北緯35.67〜35.71度）の人口を数える例です（結果は約19万2千人）。

```sql
INSTALL httpfs; LOAD httpfs; INSTALL spatial; LOAD spatial;
SELECT round(sum(pop_total)) AS pop, round(sum(pop_65_over)) AS pop_65_over
FROM read_parquet('https://catalog.shi-works.com/gtfs-gis/population-mesh-100m-2020/gtfs-gis-population-mesh-100m-2020.parquet')
WHERE bbox.xmin >= 139.73 AND bbox.xmax <= 139.78
  AND bbox.ymin >= 35.67 AND bbox.ymax <= 35.71;
```

`bbox` 列で範囲を絞ると、必要な部分だけを読みます。全国を読むと約172 MB です。

市区町村ごとの人口にするときは、行政区域（[jp-ksj/admin-boundaries](../../jp-ksj/admin-boundaries/README.md)）と、メッシュの中心点で空間結合します。東京都の合計は14,043,484人（国勢調査は14,047,594人）、鳥取県は553,071人（同553,407人）になり、公表値との差は0.1%未満です。全国の結合は、手元の DuckDB で4分ほどかかります。

QGIS など GDAL の Parquet ドライバを持つソフトでは、ファイルをダウンロードしてそのまま開けます。

## 使ってよいこと・いけないこと

- 広い範囲の人口の分布を見ること、ある範囲（駅から1km、道路から300m、市区町村など）の人口を足し上げることに使えます。
- **1つのメッシュの値は、そのメッシュの実際の人口ではありません。** 250mメッシュの人口を、建物の面積で機械的に按分した推計です。メッシュ1つの値を見て「ここに何人住んでいる」と言うことはできません。
- 国土数値情報の都市地域土地利用細分メッシュで「工場」「公共施設等用地」「公園・緑地」「ゴルフ場」の100mメッシュには、原則として人口を配分していません（作成者の説明による）。
- 国勢調査の常住人口（夜間の人口）です。昼間の人口や、通勤・通学で集まる人の数ではありません。

## 既知の注意点

- **値は小数です。** 按分した推計なので、0.01人のような値もあります。総人口が1人未満のメッシュは777,371行です。元の CSV が小数第4位までなので、ごく小さい値は0になっていて、総人口が0の行が26行あります。
- **総人口は年齢区分の和と一致しません。** 全国で、総人口（126,128,118人）は0〜14歳・15〜64歳・65歳以上の和（123,196,289人）より約293万人多くなっています。年齢不詳の人を含むためと考えられます。年齢区分の割合を出すときは、3区分の和で割ってください。
- **75歳以上と85歳以上は内数です。** `pop_75_over` は `pop_65_over` に、`pop_85_over` は `pop_75_over` に含まれます。足し合わせないでください。
- **海沿いのメッシュは、行政区域の外に出ることがあります。** メッシュの中心点で行政区域と結合すると、13,606メッシュ（60,887人）がどの市区町村にも入りませんでした。市区町村ごとの合計が公表値より少し少ないのはこのためです。
- **元データの shape ファイルは使っていません。** 1次メッシュ別の zip に入っている shape ファイルは、総人口が0.1人未満のメッシュ（99,499件）で総人口の値が100倍・1,000倍になっていて、全国の合計が126,684,737人になります。同じ zip の CSV は正しい値で、ここでは CSV の値を使っています。形はメッシュコードから計算しました（shape ファイルの形と一致します）。
- **1次メッシュ 5434 のファイルは、ダウンロードのページにリンクがありますが、取れません（404）。** 北緯36度〜36度40分、東経134〜135度の、京都府・兵庫県の沖の海だけの区画で、人の住むメッシュはないと考えられます。

## 列

<!-- columns:start -->
| 列 | 型 | 説明 |
|---|---|---|
| `mesh_code` | string | 元の列名: Meshcode。100mメッシュのコード（10桁の文字列）。3次メッシュ（約1km）のコード8桁に、3次メッシュを縦横10等分した区画の番号（緯度方向1桁、経度方向1桁）を足したもの。1行に1つで、重複しない。 |
| `pop_total` | double | 元の列名: PopT。総人口（推計。小数を含む）。国勢調査の250mメッシュの人口を、建物の面積で100mメッシュに按分した値。年齢3区分の和より大きいことがある（全国で約293万人多い。年齢不詳を含むためと考えられる）。 |
| `pop_0_14` | double | 元の列名: Pop0_14。0〜14歳の人口（推計。小数を含む）。 |
| `pop_15_64` | double | 元の列名: Pop15_64。15〜64歳の人口（推計。小数を含む）。 |
| `pop_65_over` | double | 元の列名: Pop65over。65歳以上の人口（推計。小数を含む）。 |
| `pop_75_over` | double | 元の列名: Pop75over。75歳以上の人口（推計。小数を含む）。pop_65_over の内数。 |
| `pop_85_over` | double | 元の列名: Pop85over。85歳以上の人口（推計。小数を含む）。pop_75_over の内数。 |
<!-- columns:end -->

`bbox` は各行の範囲（GeoParquet 1.1 の bbox 列）、`geometry` は100mメッシュの範囲（ポリゴン）です。

## 加工の記録

「令和2年簡易100mメッシュ人口データのダウンロード」のページにある1次メッシュ別の zip（150個）の CSV から、このリポジトリの [`scripts/gtfs-gis-population-mesh-100m-2020/build.py`](https://github.com/shiwaku/shi-works-catalog/blob/main/scripts/gtfs-gis-population-mesh-100m-2020/build.py) で次のように作りました。

1. 150個の CSV をつなぐ（4,979,919行。メッシュコードの重複なし）
2. 列名を英語の snake_case にする
3. メッシュコードから100mメッシュの長方形（緯度3秒×経度4.5秒）を作る
4. `portolan add` で、Hilbert 曲線の順に並べ、bbox 列を足し、GeoParquet 1.1 で書き直す
