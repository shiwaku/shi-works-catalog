# GeoParquet の作成規則

最終更新: 2026-11-02（#9。行グループは #19 で実際の値に直した）

ベクタの正本は GeoParquet にする（[requirements.md](requirements.md) 第3章）。タイルは事前に作らず、Worker がリクエストのたびに GeoParquet から作る（第4章）。そのため、タイル1枚に要る部分だけを読めるかどうかが、速さと費用を決める。この文書は、そのための作り方を決める。

根拠は Portolan の仕様（[formats.md](https://github.com/portolan-sdi/portolan-spec/blob/main/specs/portolan/formats.md) の GeoParquet の節）と、portolan-cli に同梱の検査ツール（rashid）の規則。

## 1. 仕様が求めること（MUST）

| 仕様 | 検査の規則 |
|---|---|
| GeoParquet 1.1 か 2.0 | PTL-DAT-012 |
| 行を空間の順に並べる（近い地物がファイルの中でも近くにある） | PTL-DAT-006 |
| 行グループごとの空間の統計を持つ（GeoParquet 1.1 の `bbox` 列と、その最小・最大の統計） | PTL-DAT-007 |
| 1つの行グループは 150,000 行以下 | PTL-DAT-008 |
| 圧縮は ZSTD を推奨（SHOULD） | — |
| 列の名前・型・説明を `collection.json` の `table:columns` に書く（SHOULD） | PTL-DAT-017（警告） |

## 2. 作り方

**portolan-cli の変換（中で geoparquet-io を使う）の既定に従う。** 既定のままで第1章を満たす。

| 項目 | 決めたこと | portolan-cli の既定 |
|---|---|---|
| GeoParquet の版 | **1.1** | 1.1 |
| 並べ方 | **Hilbert 曲線** | `hilbert` |
| bbox 列 | **持たせる** | `add_bbox: true` |
| 圧縮 | **ZSTD** | ZSTD |
| 行グループ | **portolan-cli の既定（122,880 行）**（上限は仕様の 150,000 行） | 行数を指定せず、DuckDB の既定の 122,880 行で書く |
| 座標参照系 | **EPSG:4326**（緯度経度） | 元データのまま |

- 2.0 にしない理由: 2.0 は Parquet の `GEOMETRY` 型を使う新しい版で、読めるツールがまだ限られる（QGIS・GDAL の版によっては読めない）。1.1 は広く読める。2.0 の読み手が揃ったら見直す。
- 行グループの大きさは、タイル1枚の読み取りに効く。小さいほど読み飛ばせる範囲が細かくなるが、フッターと要求の数が増える。portolan-cli の既定（122,880 行）で始めて、#8（動的タイル配信の検証）で測って見直す。変えるときは、`portolan add` の前に geoparquet-io で行数を指定して書き、portolan-cli に書き直させない（規則に合ったファイルはそのまま使われる）。
- 最初の案では 100,000 行としていたが、portolan-cli は行数を指定しないことが #19 でわかった。仕様の上限に収まるので、既定に合わせた。
- 正本は EPSG:4326 にそろえる。平面直角座標系などのデータは変換して載せ、元の座標系は README に書く。

## 3. 列

- **列名は英語の snake_case にする。** 英小文字・数字・アンダースコアだけ。先頭は英字。例: `party_a_age`、`fatalities`。
  - 日本語の列名は、SQL で毎回引用符が要り、ツールによっては文字化けする。海外の利用者も使えるようにする。
  - Portolan の多言語の推奨では、列名はどの言語版でも同じにする（[metadata.md](metadata.md) 第2章）。列名は識別子として扱い、意味は説明に書く。
  - 元の日本語の列名は、列の説明（`table:columns` の `description`）の先頭に書く。元データと突き合わせられるようにする。
- **型を正しく付ける。** 件数・人数は整数、年月日・時刻は整数か日時型、コードは文字列（先頭の 0 を落とさない）。元データが全部文字列でも、そのまま文字列にしない。
- **日時の列を1つ持たせる。** 年・月・日・時・分が別々の列なら、それとは別に日時型の列（例: `occurred_at`。タイムゾーンは日本時間 `+09:00`）を足す。期間の範囲（`extent.temporal`）を出すためと、利用者が絞り込みやすくするため。
- **コードとラベル。** 元データがコードのときに、コードとラベル（日本語）のどちらを持たせるか、両方にするかはデータごとに決める。どちらにしても、コード表は README と AGENTS.md に書く。
- **同じ意味の列を重ねない。** たとえば度分秒の緯度経度は、ジオメトリがあれば要らない。元の値を残すかはデータごとに決め、残すなら説明に書く。

## 4. 不正な座標

- 座標が明らかにおかしい行（`(0, 0)`、国の外、緯度経度の入れ違いなど）は、**行を残してジオメトリを空（null）にする。** 件数が提供元の公表値と合わなくなるのを避けるため。範囲（bbox）も正しく出る。
- 何件あったか、どう判定したかを README と AGENTS.md に書く。

## 5. ファイルの大きさと分割

- 1ファイルで済むものは1ファイルにする。Portolan の目安は「2 GB を超えたら分割を考え、1ファイル 200 MB〜1 GB にする」（formats.md）。分割の仕方は [naming.md](naming.md) 第6章（都道府県コード、国コード）。
- Cloudflare の Free プランでは、512 MB を超えるファイルはエッジでキャッシュされない（requirements.md 第8章）。Worker が R2 から直接読む方式（第4章の方式②）ならキャッシュの上限は関係しないが、ブラウザや DuckDB が `catalog.shi-works.com` から直接読むときは影響する。512 MB〜2 GB のファイルの扱いは #8 で決める。

## 6. 作業の記録

- 変換に使ったスクリプトかコマンドを、そのまま AGENTS.md に書く（Portolan のベストプラクティス、[documentation.md](https://github.com/portolan-sdi/portolan-spec/blob/main/specs/best-practices/documentation.md)）。変換のスクリプトがこのリポジトリの外（データごとの変換リポジトリ）にあるときは、リポジトリとコミットを書く。
- 作ったら `portolan check --strict` で確かめる。第1章の検査（PTL-DAT-006、007、008、012）はファイルの中身を読んで行う。

## 7. 第1段階（交通事故統計）での当てはめ

`jp-npa/traffic-accident/jp-npa-traffic-accident.parquet`（#19）。

| 項目 | 今のファイル（`npa-traffic-accident-analytics`） | 作り直したあと |
|---|---|---|
| 行数 | 2,182,298（2019〜2025年の本票） | 同じ |
| 版 | GeoParquet 1.0.0 | 1.1 |
| 並び | 統計に計上された年の順 | Hilbert 曲線 |
| bbox 列 | なし | あり |
| 行グループ | 131,072 行 × 17 | 122,880 行 × 18 |
| 圧縮 | ZSTD レベル 9 | ZSTD |
| 大きさ | 112 MB | 132 MB（空間の順に並べたため、年の順より圧縮が効きにくい） |
| 列名 | 日本語 | 英語の snake_case |
| 型 | すべて文字列 | 件数・人数・年月日・時刻は整数、日時型の列（`occurred_at`）を追加 |
| 値 | ラベル（4項目はコードのまま） | ラベル。オートマチック車・サポカー・運転練習の方法もラベルにした。認知機能検査経過日数は日数のコードのまま |
| 緯度経度の列 | 度分秒と10進数 | 除く（ジオメトリにある） |
| 不正な座標 | `(0, 0)` が 150 件、日本の外が 21 件 | 行は残し、ジオメトリを空にする |
| 統計に計上された年 | `資料年次` の列（analytics で追加） | 引き継ぐ |

- 年の順から空間の順に並べ替えるので、年で絞ったときに読み飛ばせる行グループは減る。ただし列指向なので、集計で読む量は列を絞ることで小さく保てる。作り直したら、年で絞った集計の転送量を測って README に書く。
- 既存の MCP サーバー（`npa-traffic-accident-analytics`）は、今のファイル（日本語の列名）を読み続ける。カタログのファイルに切り替えるかは、移行（#7）のときに決める。
